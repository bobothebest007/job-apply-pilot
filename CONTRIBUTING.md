# Contributing

Issues and pull requests are welcome for reproducible improvements to the workflow.

1. Describe the application-system behavior and the expected result. Remove names, résumés, contact details, tokens, and application answers from examples and screenshots.
2. Keep `SKILL.md` focused on reusable steps, not one employer's form or one user's preferences. Put longer explanations in the README.
3. Validate the skill frontmatter and read the instructions end to end. If you change a browser-specific procedure, explain which driver and form type you tested.
4. Use a one-line [Conventional Commit](https://www.conventionalcommits.org/) message for commits, such as `docs: clarify tracker verification`.

Please do not submit real application data or credentials, even in issue attachments or git history.
